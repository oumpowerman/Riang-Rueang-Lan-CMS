# ระบบลบคลิปหลัก (EP) และถอดฟุตเทจรายอันดับในหน้าต่างจัดการตอน

เพิ่มความสามารถในการจัดการวงจรชีวิตข้อมูลของคลิปหลัก (Master Episode) อย่างสมบูรณ์ 2 ส่วนภายในหน้าต่างรายละเอียดคลิปหลัก ได้แก่ ปุ่ม **ลบคลิปหลัก (EP)** พร้อมหน้าต่างยืนยันความปลอดภัยก่อนลบบน Cloud และปุ่ม **ถอดฟุตเทจออกจากอันดับ** รายช่องในโหมดแก้ไขเพื่อล้างข้อมูลทุกช่องในอันดับนั้นให้ว่างอย่างปลอดภัย

## User Review & Critical Decisions

> [!IMPORTANT]
> แผนนี้อ้างอิงจากการยืนยันความต้องการของผู้ใช้งานครบทั้ง 3 ข้อแล้ว หากต้องการปรับเงื่อนไขเพิ่มเติมสามารถแจ้งปรับแก้ก่อนกดดำเนินการได้ทันที

- **ขอบเขตฟีเจอร์ที่ยืนยันแล้ว**: เพิ่มครบทั้ง 2 ความสามารถ ได้แก่ **ปุ่มลบคลิปหลักทั้งตอน (EP)** และ **ปุ่มถอดฟุตเทจออกจากรายอันดับ**
- **ตำแหน่งของปุ่มลบคลิปหลัก (EP)**: แสดงเฉพาะภายใน **หน้าต่างรายละเอียดคลิปหลัก (EP Modal)** เท่านั้น เพื่อป้องกันการเผลอกดลบจากหน้าคลังรวมและรักษาความสะอาดตาของมุมมองการ์ด/ตาราง
- **พฤติกรรมเมื่อกดถอดฟุตเทจออกจากอันดับ**: ล้างข้อมูล **ทุกช่องในอันดับนั้นให้ว่างทั้งหมด** (รหัสฟุตเทจ, ชื่ออันดับ, คำสร้อย, บทพากย์มาสคอต, บันทึกตอนผสม และสถานะล็อกเฉพาะ EP) โดยทำงานบนสถานะร่าง (Draft) เพื่อตรวจทานก่อนกดบันทึก

---

## 1. Overview & Core Concept

- **What It Does**: เปิดให้ทีมงานคอนเทนต์สามารถลบคลิปหลักที่สร้างผิดหรือยกเลิกแผนผลิตได้จากหน้าต่างรายละเอียดคลิปหลักโดยมีหน้าต่างยืนยันซ้ำ (Delete Confirmation Dialog) และสามารถถอดฟุตเทจออกจากอันดับใดอันดับหนึ่งระหว่างจัดส่วนผสมใหม่ได้ในคลิกเดียว
- **Target Audience / Persona**: ทีมโปรดิวเซอร์, นักเขียนบทมาสคอต และผู้ดูแลคลังคลิป 5 อันดับ ที่ต้องการความยืดหยุ่นในการแก้ไขส่วนผสมและเคลียร์ตอนซ้ำซ้อนโดยไม่ทำลายฟุตเทจต้นฉบับในคลัง
- **Key Value**: ลดความผิดพลาดจากการแก้ข้อมูลแบบกึ่งลบ ป้องกันการลบตอนสำคัญโดยไม่ตั้งใจ และช่วยให้สถานะความสมบูรณ์ของคลิปหลัก (เช่น ฟุตไม่ครบ X/5) รวมถึงสิทธิ์ Cooldown ของฟุตเทจย่อยในคลังคำนวณใหม่อัตโนมัติแบบเรียลไทม์

## 2. User Experience & Visual Design

### Key User Flows

1. **การลบคลิปหลักทั้งตอน (Delete Master Episode Flow)**:
   - ผู้ใช้เปิด **หน้าต่างรายละเอียดคลิปหลัก (EP Modal)** จะพบปุ่ม **ลบคลิปหลัก** โทนพาสเทลแดง/กุหลาบอ่อนอยู่ในส่วนหัวของหน้าต่าง (และในแถบจัดการเมื่อเข้าสู่โหมดแก้ไข)
   - เมื่อคลิก ระบบเปิด **หน้าต่างยืนยันการลบ** (Render ผ่าน Portal ชั้นบนสุดเหนือหน้าต่างหลัก) แสดงรหัส EP ชื่อคลิป จำนวนฟุตเทจที่ผูกอยู่ และคำอธิบายชัดเจนว่า:
     - ข้อมูลคลิปหลัก (EP) นี้จะถูกลบออกจากคลังและ Cloud ถาวร
     - **ฟุตเทจย่อยทั้ง 5 ชิ้นจะยังคงอยู่ในคลังฟุตเทจอย่างปลอดภัย** ไม่ถูกลบตาม และประวัติการใช้งาน / ระยะพัก Cooldown จะอัปเดตคืนสิทธิ์ให้อัตโนมัติ
   - ผู้ใช้กดปุ่ม **ยืนยันลบคลิปหลัก** ระบบแสดงสถานะกำลังดำเนินการสั้นๆ ระหว่างบันทึกบน Cloud เมื่อสำเร็จจะปิดหน้าต่างทั้งสองชั้นกลับสู่คลังคลิปหลักทันที (หาก Cloud ขัดข้องจะแสดงข้อความแจ้งเตือนภายในหน้าต่างยืนยันโดยไม่ปิดหนี)

2. **การถอดฟุตเทจออกจากอันดับ (Remove Footage from Rank Slot Flow)**:
   - ผู้ใช้กดปุ่ม **แก้ไขรายละเอียด & ส่วนผสม** เพื่อเข้าสู่โหมดแก้ไขรายการ 5 อันดับ
   - บนการ์ดของแต่ละอันดับ (#5 ถึง #1) ที่มีฟุตเทจหรือข้อความค้างอยู่ จะมีปุ่ม **ถอดฟุตเทจ** คู่กับปุ่ม **เลือก / เปลี่ยนฟุตเทจ** ในแถบควบคุมด้านบนของอันดับนั้น
   - เมื่อกด **ถอดฟุตเทจ** ระบบล้างข้อมูลทุกช่องในอันดับนั้นให้ว่างทันที (รหัสฟุต, ชื่ออันดับ, คำสร้อย, บทมาสคอต, บันทึกตอนผสม และปลดโหมดปรับแต่งเฉพาะ EP) และเปลี่ยนมุมมองการ์ดอันดับนั้นเป็นสถานะช่องว่าง พร้อมปุ่มทางลัด **เลือกฟุตเทจใส่** เผื่อต้องการเติมคลิปใหม่ทันที หรือกด **บันทึกการแก้ไข** เพื่อยืนยันเก็บเป็นสถานะว่าง
   - เมื่อบันทึกแล้ว ในหน้าดูรายละเอียด (Read-only) อันดับที่ถูกถอดจะแสดงข้อความ **ว่าง (ยังไม่ได้เลือกฟุตเทจ)** อย่างสะอาดตา (ไม่แสดงป้ายซิงก์ Realtime หลอกตา) และตัวนับสัดส่วนบนหัวคลิปหลักรวมถึงตัวกรองคลังจะระบุเป็น **ฟุตไม่ครบ (X/5)** โดยอัตโนมัติ

### Visual Identity & Theme

- **Aesthetic Direction**: คงอัตลักษณ์ **Light Pastel Earth-Tone Enterprise** ที่สงบ สว่าง และอ่านง่ายสบายตา
- **Color Palette & Mood**:
  - พื้นหลังหน้าต่างหลักและผิวการ์ด: โทนครีม-งาช้างสว่าง (`#FFFFFF`, `#FAF7F2`) ตัดเส้นขอบละเอียด (`#E8DFD3`)
  - ปุ่มและการแจ้งเตือนเชิงลบ/การลบ (Destructive Action): ใช้โทน **Pastel Rose / Terracotta อ่อน** (พื้น `#FFF5F5` ขอบ `#F3C7C7` ข้อความ `#9E2A2B` และปุ่มยืนยันสี `#B43C3E`) เพื่อสื่อสารความเสี่ยงชัดเจนโดยไม่ฉูดฉาด
  - ตัวอักษรและตัวเลขสรุปสถิติ: ใช้ Sans ภาษาไทยที่คมชัด (`Plus Jakarta Sans` + `IBM Plex Sans Thai`) คู่กับตัวเลข `tabular-nums` จัดแนวคอลัมน์ตรงกันทุกจุด
- **Component Styling & Layout**:
  - หน้าต่างยืนยันการลบสร้างบนโครงสร้าง **BaseModal Wrapper + React Portal** แยกชั้น Z-index เหนือ EP Modal ได้ 100%
  - ปรับความกว้างและความสูงให้รองรับทั้ง Desktop และ Mobile (Responsive Stack บนหน้าจอแคบ ปุ่มกดมีระยะสัมผัสเพียงพอและเรียงเป็นแนวตั้ง/แนวนอนอัตโนมัติ) พร้อม **Slim Custom Scrollbars**

### Interactive Feedback & Motion

- ใช้ Framer Motion เฉพาะการเคลื่อนไหวเปิดตัว-ปิด (`opacity` + `scale` + `y` แบบสปริงนุ่มนวล จบภายใน 200ms) แยกขาดจากเลย์เอาต์ของ CSS
- ปุ่มลบในหน้าต่างยืนยันแสดงสถานะกำลังลบ (Disabled + Spinner) ป้องกันการกดเบิ้ลระหว่างรอผลจาก Cloud

## 3. Key Product Decisions & Trade-Offs

- **Decision 1: รอผลลัพธ์จาก Cloud ในการลบ EP ก่อนปิดหน้าต่าง (Async Cloud Confirmation)**
  - *Chosen Approach*: ปรับฟังก์ชันลบ EP ให้คืนค่าสถานะการทำงานแบบ Async (`Promise`) เพื่อให้หน้าต่างยืนยันแสดงสถานะรอผลสั้นๆ และแจ้งเตือนได้ทันทีหากเชื่อมต่อไม่สำเร็จ
  - *Why*: การลบทั้ง EP เป็นการเปลี่ยนแปลงถาวร การยืนยันว่าคำสั่งลบสำเร็จบน Cloud จริงก่อนปิดหน้าต่างช่วยสร้างความมั่นใจว่าข้อมูลไม่เด้งกลับมาภายหลัง
  - *Alternatives Considered*: ลบในหน้าจอทันทีแล้วส่งคำสั่งเบื้องหลังเงียบๆ (Optimistic Fire-and-Forget) ซึ่งเสี่ยงที่ผู้ใช้คิดว่าลบแล้วแต่จริง ๆ เครือข่ายหลุด

- **Decision 2: การถอดฟุตเทจทำงานบน Draft State และล้างข้อมูลทุกช่องในอันดับนั้นทันที**
  - *Chosen Approach*: เมื่อกดปุ่มถอดฟุตเทจในโหมดแก้ไข ระบบล้างทุกช่องในอันดับนั้นทันทีในร่าง (Draft) โดยไม่ต้องเปิด Modal ซ้อนอีกชั้น เพราะผู้ใช้สามารถกด **ยกเลิก** ที่แถบเครื่องมือเพื่อคืนค่าเดิมทั้งหมดได้ก่อนกด **บันทึกการแก้ไข**
  - *Why*: ลดจำนวนคลิกที่ซ้ำซ้อนระหว่างจัดอันดับ 5 คลิป ขณะเดียวกันยังมีปุ่มยกเลิกรวมทำหน้าที่เป็นตาข่ายนิรภัย (Safety Net) อยู่แล้ว

- **Decision 3: แตกโมดูลย่อยเพื่อคุมขนาดไฟล์ตามมาตรฐาน Enterprise (< 800 บรรทัด)**
  - *Chosen Approach*: แยก **หน้าต่างยืนยันการลบ EP** และ **ส่วนฟอร์มแก้ไขลิงก์ไฟล์คลิปหลัก (Master Links)** ออกเป็นคอมโพเนนต์ย่อยเฉพาะทาง
  - *Why*: ปัจจุบันคอมโพเนนต์หลักของ EP Modal มีขนาดเกิน 800 บรรทัดแล้ว การแยกส่วนย่อยช่วยให้โครงสร้างสะอาด ดูแลรักษาง่าย และไม่เกิดไฟล์ขนาดใหญ่เกินเกณฑ์สถาปัตยกรรม

### Data Model & State

- **Rank Slot Cleared Shape (`footageId: null`)**: เมื่อถอดฟุตเทจออก ช่องอันดับนั้นยังคงรักษาลำดับ `rank` (5 ถึง 1) เอาไว้ แต่รีเซ็ตค่าภายในทั้งหมด:
  - `footageId`: `null`
  - `rankTitle`: `""`
  - `punchlineNote`: `""`
  - `mascotScript`: `""`
  - `snapshotNote`: `""`
  - `isCustomOverride`: `false`
- **Cascading Impact**:
  - ตัวประเมินความสมบูรณ์ของคลิปหลักจะนับจำนวนฟุตที่มีอยู่จริงเทียบกับ 5 อันดับ ทำให้คลิปที่ถูกถอดฟุตออกถูกจัดเป็น **ข้อมูลหรือลิงก์ไม่ครบ (`ฟุตไม่ครบ X/5`)** ทันที
  - ตัวคำนวณประวัติการใช้งานฟุตเทจจะดึงข้อมูลสดจากรายการตอนทั้งหมด ดังนั้นทั้ง **การลบ EP** และ **การถอดฟุตเทจออกจากอันดับแล้วบันทึก** จะอัปเดตตัวนับการใช้ซ้ำและวัน Cooldown ของฟุตเทจนั้นให้ถูกต้องทั้งระบบโดยอัตโนมัติ

### Interactive Component & State Mapping

- **Delete Trigger & Confirmation Sub-Modal**: เก็บ Local State `isDeleteConfirmOpen`, `isDeleting`, `deleteError` ไว้ควบคุมหน้าต่างยืนยันบน Portal แยกชั้น เหนือกว่า EP Modal ป้องกันปัญหา Z-index ซ้อนทับ เมื่อการลบเสร็จสมบูรณ์จะเคลียร์ `selectedEpisodeDetailId` เพื่อปิด Modal ทันที
- **Rank Removal Action**: รับ Callback `onRemoveSlotFootage(rank)` เพื่อรีเซ็ตช่องใน `draftRankings` เฉพาะตำแหน่งที่ระบุ พร้อมปรับการแสดงผลในส่วน Read-Only และตัวนับ Mix ("ใหม่ / วนใช้") ให้คำนวณจากฟุตเทจที่มีอยู่จริง ไม่ยึดค่าคงที่ 5 ชิ้นตายตัว
- **Empty Slot Rendering**: ในมุมมองตารางรายละเอียด เมื่อ `slot.footageId === null` จะแสดงสถานะช่องว่างอย่างชัดเจนแทนข้อความ Error ไม่พบข้อมูลและไม่ติดป้ายสถานะซิงก์ Realtime
